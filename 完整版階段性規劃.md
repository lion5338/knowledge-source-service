# Knowledge Source Service 完整版階段性規劃

本文件根據 2026-07-29 對 `core/knowledge-source-service` 全部程式碼、migration、script、README 與 schema 說明文件的閱讀結果整理。

`knowledge-source-service` 是 Question Generation 系統的 source ingestion 與 artifact service。它的目標是把原本散落在 `ai-workflow-service/knowledge` 底下的 source registry、raw snapshot、normalized artifact、mapping artifact、report artifact 與 runtime knowledge index 移到獨立服務，讓 ai-workflow-service 只透過 API consume runtime index。

## 1. 服務邊界

### 1.1 本服務負責

```text
knowledge source registry
source version metadata
raw snapshot artifact metadata
normalized artifact metadata
mapping artifact metadata
report artifact metadata
runtime index artifact
artifact storage read API
source/version/artifact list API
latest runtime index API
import compatibility bridge from ai-workflow-service/knowledge
source artifact audit events
```

### 1.2 本服務不負責

```text
question generation
prompt synthesis
topic approval / review
approved prompt context
LLM synthesis
teacher UI
runtime validator / renderer
tenant policy
full normalization pipeline, until later phases
```

### 1.3 和其他服務的關係

```text
knowledge-source-service
  owns source artifacts and runtime index publication

knowledge-synthesis-service
  owns reviewed synthesis, prompt context, topic registry, claims

ai-workflow-service
  consumes latest runtime index and generates questions
```

目前 ai-workflow-service 可透過：

```text
KNOWLEDGE_SOURCE_BASE=http://127.0.0.1:3200/v1
GET /v1/runtime-index/latest
```

若 service 不可用，ai-workflow-service 仍會 fallback 到 local bootstrap index。

## 5. Phase K2：Compatibility Import Bridge

目標：先把既有 `ai-workflow-service/knowledge` 搬進本服務，讓 microservice boundary 可以先跑起來。

核心 script：

```text
scripts/import/import-ai-workflow-knowledge.mjs
```

目前行為：

```text
讀取 ai-workflow-service/knowledge
複製到 knowledge-source-service/storage/knowledge
讀 sources.json
upsert knowledge_source_registry
upsert knowledge_source_versions
遞迴列出 storage files
依 path 推導 artifact_id
依 path 推導 artifact_type
計算 sha256
upsert knowledge_source_artifacts
寫 knowledge_source_audit_events
```

artifact type 推導：

```text
raw/*        -> raw_snapshot_file
normalized/* -> normalized_artifact
mappings/*   -> mapping_artifact
index/*      -> runtime_index
reports/*    -> report_artifact
sources.json -> source_registry_config
else         -> knowledge_artifact
```

尚缺：

```text
不是正式 source sync
不是正式 normalization pipeline
不是正式 mapping/publish job
不支援 incremental import
不支援 rollback
不支援 artifact lineage graph
```

### 11.4 最大風險

```text
1. 目前是 compatibility bridge，真正 ingestion / normalization / mapping 還沒搬進本服務。
2. latest runtime index 依賴已存在的 runtime-index:latest artifact，尚未由本服務建置發布。
```

## 12. 依 AI Workflow 修正版產品節奏排序

本節依 `ai-workflow-service` 修正版 roadmap 重新排序 `knowledge-source-service` 的部分完成與尚未實作工作。原則是先讓 demo MVP 能穩定追溯 runtime index，再支援台灣官方課綱與教材 RAG，最後才補 tenant、Hermes、部署與營運治理。

### 12.1 Demo MVP 確認市場

目標：讓 ai-workflow-service demo 期間可以穩定透過 API 取得 runtime index，且每次 fallback / artifact 版本都可追蹤。

部分完成優先收斂：

| 優先 | 功能 | 目前狀態 | 收斂目標 | 20260729 進度盤點 |
|---|---|---|---|---|
| 1 | Microservice boundary | AI Workflow 可讀 latest runtime index，並 fallback local。 | 加入 artifact_id、checksum、source、fallback reason，讓 trace 可重現。 | knowledge-source-service 端已提供 latest runtime index trace metadata、artifact id、checksum、publish status 與 OpenAPI contract；fallback reason 仍需由 ai-workflow-service consumer 端記錄。 |
| 2 | Runtime index service | 可讀 `runtime-index:latest`。 | 支援 runtime index version pinning 與 latest metadata。 | 已完成 Demo MVP 收斂：`runtime-index:latest` 作為 alias，metadata 指向 immutable `runtime-index:sha256:<checksum>` pinned artifact，latest response 回 alias、version、checksum、publish_status、summary、trace_mode。 |
| 3 | Artifact registry | 可保存 artifact metadata、checksum、storage path。 | 補 artifact version history / publish status first pass。 | 已完成 publish_status first pass 與 runtime index immutable version history；一般 artifact type 的完整版本歷史仍留待後續 artifact lineage/history slice。 |
| 4 | Import bridge | 可搬 ai-workflow-service knowledge folder。 | 強化成可重跑、可比較、可回報 import summary 的 demo bootstrap。 | 已完成：import 會產出 summary，統計 source/artifact 數量、created/changed/unchanged、runtime index checksum/status，並同步寫入 audit event 與 `reports/latest-import-summary.json`。 |
| 5 | Storage | local filesystem 可用。 | 先補 ETag/cache metadata 與 read observability，不急著換 object storage。 | 已完成 Demo MVP 收斂：artifact/runtime-index read response 回 ETag、Cache-Control、trace/cache headers；Redis 可選 response cache 已支援，未設定 Redis 時維持原本 local/no-cache 模式。 |

尚未實作優先新增：

| 優先 | 功能 | 所屬 Phase | Demo MVP 做到哪裡 | 20260729 進度盤點 |
|---|---|---|---|---|
| 1 | Runtime index diff | K6 | 先支援比較 latest 與上一版 topic/source 變動。 | 已完成：`GET /v1/runtime-index/diff` 支援 default latest vs previous published pinned version，也支援 explicit `from` / `to` artifact ids，回 topics/sources/source-ref added/removed/changed summary。 |
| 2 | Artifact version history | K3 / K6 | 可查 runtime index 與 artifact 歷史版本。 | Demo MVP 已完成 runtime index version history：每次 import 保留 immutable pinned runtime index artifact，可透過 artifact list/filter 與 pinned artifact id 查詢；一般 artifact version history 尚未完整泛化。 |
| 3 | Publish status | K1 / K4 | 至少有 imported / validated / published / deprecated。 | 已完成：DB migration、artifact response、artifact detail/list、OpenAPI 與 query filter 均支援 `imported` / `validated` / `published` / `deprecated`。 |
| 4 | OpenAPI contract | K7 | 先描述 runtime-index / artifact read API，供 AI Workflow client 對齊。 | 已完成：`openapi/knowledge-source-service.openapi.yaml` 與 `GET /openapi.json` 已提供 Demo read API contract，並有 `npm run openapi:validate` 驗證。 |
| 5 | API auth | K7 | Demo 可先用 optional service key，不進 tenant account 系統。 | 已完成：設定 `KNOWLEDGE_SOURCE_KEY` 時啟用 `Authorization: Bearer <key>`；runtime-index/artifact demo read APIs 受保護，`/openapi.json`、`/healthz`、`/readyz` 保持開放。 |

完成門檻：

```text
AI Workflow 每次 demo 出題都能追到使用 remote 或 local index、artifact id、checksum、fallback reason。
knowledge-source-service 仍可用 compatibility import 支撐 demo，不必先完成完整 ingestion pipeline。
```

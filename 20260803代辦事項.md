# 20260803 代辦事項

本文整理 `knowledge-source-service` 接下來要支援
`demo / mvp / prod` runtime index profile 的實作路線。

核心 env 設計：

```env
KNOWLEDGE_SOURCE_RUNTIME_PROFILE=demo
```

允許值：

```text
demo
mvp
prod
```

## 0. Profile 定義與總體邊界

### Spec

```text
demo:
  用於 Phase 1.3 Demo MVP Market Validation。
  允許把整個 K12-Dataset demo topic graph 發布成 runtime 可解析 topic。
  只能宣稱 demo / non-commercial / external_baseline。

mvp:
  用於 Phase 1.5 Taiwan official curriculum structuring
  與 Phase 2 Taiwan curriculum + materials RAG 完成後。
  runtime index 改以台灣官方課綱與 approved materials 為主。

prod:
  用於 Phase 2.5 User / tenant accounts, limits, and runtime policy 完成後。
  在 mvp base index 上加入 user/tenant-specific source overlay。
  同時保持台灣課綱 + 補教自編來源，但要受 user/tenant policy 控制。
```

### 如何做

```text
1. 新增 profile config reader：
   KNOWLEDGE_SOURCE_RUNTIME_PROFILE=demo|mvp|prod

2. runtime index artifact alias 改成 profile-aware：
   runtime-index:demo:latest
   runtime-index:mvp:latest
   runtime-index:prod:latest

3. `/v1/runtime-index/latest` 根據 active profile 回傳對應 index。

4. import/build/publish script 必須帶 profile metadata。

5. 每個 profile 都要有 source policy gate，避免 demo source 誤進 mvp/prod。
```

### 驗收門檻

```text
1. `.env.local` 可用 KNOWLEDGE_SOURCE_RUNTIME_PROFILE 切換 active runtime index。
2. API response trace metadata 顯示 active profile。
3. 不同 profile 不會共用錯誤 artifact alias。
4. demo profile 可以發布 K12 demo graph。
5. mvp/prod profile 不可默默使用 demo/non-commercial-only source。
```

## 1. Batch KS-A：Profile Config 與 Artifact Alias

### 實作順序

```text
1. 新增 runtime profile config module。
2. 定義允許值 demo / mvp / prod。
3. 將 invalid profile fail fast。
4. 新增 profile-aware artifact id helper。
5. 補 unit test。
```

### Spec

```text
新增 module：
src/lib/runtime-profile.js

輸出：
getRuntimeProfile()
runtimeIndexAliasForProfile(profile)
runtimeIndexPinnedArtifactPrefix(profile)
assertSupportedRuntimeProfile(profile)

artifact 命名：
runtime-index:demo:latest
runtime-index:demo:sha256:<checksum>
runtime-index:mvp:latest
runtime-index:mvp:sha256:<checksum>
runtime-index:prod:latest
runtime-index:prod:sha256:<checksum>
```

### 如何做

```text
1. 從 process.env.KNOWLEDGE_SOURCE_RUNTIME_PROFILE 讀值。
2. 預設值可先用 demo，避免本地開發空值時無法啟動。
3. route 和 import script 不直接讀 env，而是透過 module。
4. 保留 legacy runtime-index:latest 讀取相容，直到 migration 完成。
```

### 驗收門檻

```text
1. KNOWLEDGE_SOURCE_RUNTIME_PROFILE=demo -> alias runtime-index:demo:latest。
2. KNOWLEDGE_SOURCE_RUNTIME_PROFILE=mvp -> alias runtime-index:mvp:latest。
3. KNOWLEDGE_SOURCE_RUNTIME_PROFILE=prod -> alias runtime-index:prod:latest。
4. invalid value 產生明確錯誤，不 fallback 到錯誤 profile。
5. npm test 通過。
```

## 2. Batch KS-B：Demo Profile K12 Topic Graph Runtime Index Builder

### 實作順序

```text
1. 讀取 K12-Dataset normalized/raw demo graph。
2. 將 K12 node 轉成 runtime topics[]。
3. 產生 aliases / keywords / retrieved_sources。
4. 標記 license_scope = non_commercial_demo_only。
5. 寫出 profile-aware runtime index artifact。
6. 補 demo-critical topic eval。
```

### Spec

```text
demo profile 必須把 K12-Dataset demo topic graph 轉成 runtime 可解析 topic。

每個 topic 至少包含：
topic_key
topic_label
aliases
keywords
learning_stage
retrieved_sources[]
mapping_status
license_scope
official_curriculum_verified=false

至少要覆蓋：
一元一次方程式
一次方程式
linear equation
one-variable linear equation
國中數學常見 K12 demo nodes
```

### 如何做

```text
1. 新增 builder script：
   scripts/runtime-index/build-demo-k12-runtime-index.mjs

2. 輸入來源：
   storage/knowledge/raw/k12-dataset/<version>/
   storage/knowledge/normalized/k12-dataset-nodes.json
   storage/knowledge/normalized/k12-dataset-edges.json

3. 若 normalized artifact 不足，先從 raw demo graph 補最低限度 mapping。

4. 建立 deterministic topic_key：
   k12_demo:<normalized_node_id>
   或 k12_demo:<slug>

5. topic aliases 要包含：
   原始 label
   簡體/繁體可接受別名
   英文翻譯別名
   source node id

6. 寫出：
   storage/knowledge/index/profiles/demo/knowledge-index.json

7. import/publish 時註冊：
   runtime-index:demo:latest
   runtime-index:demo:sha256:<checksum>
```

### 驗收門檻

```text
1. demo runtime index topic_count 大於目前 9 個 MVP seed topics。
2. `一元一次方程式` 可以在 topics[].aliases 或 topic_label 中找到。
3. topic resolver 對以下 prompt 必須 resolved：
   請幫我出 1 題國中數學「一元一次方程式」的應用題，難度中等，附答案與解析。
4. response metadata 顯示 profile=demo。
5. 所有 k12_dataset source refs 都保留 attribution。
6. official_curriculum_verified=false。
7. production/mvp profile 不會讀到 demo K12 index。
```

## 3. Batch KS-C：Profile-Aware Runtime Index Latest API

### 實作順序

```text
1. 修改 getLatestRuntimeIndex() 支援 profile。
2. `/v1/runtime-index/latest` 讀 active profile alias。
3. response headers 加入 profile metadata。
4. 保留 legacy fallback。
5. 補 API tests。
```

### Spec

```text
GET /v1/runtime-index/latest

根據 KNOWLEDGE_SOURCE_RUNTIME_PROFILE 回傳：
demo -> runtime-index:demo:latest
mvp  -> runtime-index:mvp:latest
prod -> runtime-index:prod:latest

response 必須包含：
profile
trace_mode
alias
version
artifact
summary
index

headers 建議包含：
X-Knowledge-Source-Runtime-Profile
X-Runtime-Index-Alias-ID
X-Runtime-Index-Version-ID
X-Artifact-ID
ETag
Cache-Control
```

### 如何做

```text
1. sources.js 的 getLatestRuntimeIndex() 接受 profile option。
2. route.js 呼叫 getRuntimeProfile()。
3. getArtifact() 改讀 profile alias。
4. 如果 profile alias 不存在：
   - demo 可提示先跑 build/import demo index。
   - mvp/prod 要明確 not_found，不可 fallback 到 demo。
5. read-response-cache key 必須包含 profile。
```

### 驗收門檻

```text
1. demo profile 回傳 runtime-index:demo:latest。
2. mvp profile 不會回傳 demo alias。
3. prod profile 不會回傳 demo alias。
4. headers 包含 active profile。
5. cache key 依 profile 隔離。
6. openapi schema 更新。
7. npm test、openapi:validate 通過。
```

## 4. Batch KS-D：AI Workflow Demo Integration Contract

### 實作順序

```text
1. 更新 ai-workflow-service 的 KNOWLEDGE_SOURCE_BASE 設定說明。
2. 確認 AI Workflow 讀 remote runtime index 時保留 profile metadata。
3. 補 cross-service smoke。
4. 對 demo-critical prompt 跑 topic resolver eval。
```

### Spec

```text
AI Workflow 使用：
KNOWLEDGE_SOURCE_BASE=http://127.0.0.1:3200/v1
KNOWLEDGE_SOURCE_KEY=<optional>

當 knowledge-source-service profile=demo：
AI Workflow topic resolver 應能解析 K12 demo graph topic。

demo-critical prompt：
請幫我出 1 題國中數學「一元一次方程式」的應用題，難度中等，附答案與解析。
```

### 如何做

```text
1. knowledge-source-service 啟動 demo profile。
2. ai-workflow-service 設定 KNOWLEDGE_SOURCE_BASE。
3. AI Workflow 清掉 local cached runtime index。
4. 呼叫 topic resolver / question generator。
5. 將 profile、artifact_id、checksum 寫入 trace。
```

### 驗收門檻

```text
1. demo-critical prompt 不再 TOPIC_AMBIGUOUS。
2. topic_resolution.status=resolved。
3. topic_resolution.index_version 來自 remote demo runtime index。
4. trace 有 knowledge_source_api.status=ok。
5. generated result 保留 source attribution。
```

## 6. Batch KS-F：Prod Profile User / Tenant Overlay

本階段等 AI Workflow roadmap 的下列階段完成後再做：

```text
Phase 2.5 User / tenant accounts, limits, and runtime policy
```

### 實作順序

```text
1. 保留 mvp runtime index 作為 base。
2. 設計 tenant/user source overlay contract。
3. 設計補教自編教材 source registry。
4. 設計 tenant-aware source filtering。
5. 設計 service-level auth 與 audit evidence。
```

### Spec

```text
prod profile 必須同時支援：
1. 台灣官方課綱 base source。
2. approved materials。
3. 補教自編教材。
4. user/tenant-specific source overlay。

knowledge-source-service 提供 source artifact 與 runtime index evidence。
AI Workflow 負責依 authContext / tenantPolicy 決定可用 source。
```

### 如何做

```text
1. runtime-index:prod:latest 提供 base prod index。
2. 另設 overlay metadata：
   tenant_id
   source_scope
   source_visibility
   allowed_roles
   publish_status

3. API 要能依 service credential 查詢 overlay。
4. trace 不可洩漏 user secret 或 private document raw content。
5. tenant filtering 必須有測試。
```

### 驗收門檻

```text
1. prod profile 不會把 A tenant 的補教自編 source 給 B tenant。
2. AI Workflow trace 只保存 safe metadata / artifact refs。
3. official curriculum base source 仍可用。
4. tenant overlay source 可被 pin 到 artifact version。
5. audit event 可追蹤 source publish / consume。
```
